📱 Oneclickrecap — Blogspot Tool (phone render)

Version: blogspot-v4-mov-mkv, 2026-10-29. Static HTML/JS only — no server, no VM, no tunnel. Everything below runs in this phone's browser. MP4, MOV and MKV files are all accepted; any file Chrome cannot play is converted to H.264 MP4 inside this page (ffmpeg.wasm, single-thread core, no CapCut needed) — see section 1.

Blogspot truth, read first: Blogspot hosts static files only. This page CANNOT download a link (YouTube/TikTok block browser downloads, yt-dlp needs a server), CANNOT transcribe audio (no Whisper server here), and does NOT call any VM (the VM tunnel is blocked). Input is a local video file from this phone. Narration script is typed/pasted by you, or generated with YOUR OWN Gemini key (optional, stored only in this browser). Render uses this phone's CPU/encoder only.

Workflow on this page, in order: 1 choose a local video file → 2 write/paste Burmese narration, auto-split into timed segments, edit them → 3 (optional) Gemini script / Gemini TTS with your own key → 4 choose narration audio (Gemini TTS / uploaded audio / original / silent) → 5 drag blur + subtitle on the Preview at the top, set font → 6 Start render → download the MP4. Keep this page open and on screen during render.

⚠️ Keep this page open and on screen. Do not switch apps or lock the phone.
The browser may throttle or stop the render in the background — exactly like DeepClip warns. Start with a short clip (30 seconds or less) first, then try longer ones.
Battery / heat warning: hardware encoding uses the phone's encoder and will warm the phone. This page tries to hold a screen wake-lock, but that does not guarantee the browser keeps rendering if you leave the page.

1. Source video (LOCAL FILE ONLY — link input does NOT work on Blogspot)

MP4, MOV and MKV files are all accepted here. If Chrome cannot play the file you chose (MOV/QuickTime is not supported in Chrome, and MKV support is codec-dependent), the 🔄 Convert button below appears and converts it to H.264 MP4 inside this phone — no rename, no CapCut, no upload anywhere. Link paste does NOT work here: browsers cannot download YouTube/TikTok videos (CORS/DRM), and there is no server to run yt-dlp. If you only have a link, download it first with the Telegram bot, then choose that file here.

Timing is an approximation, not per-segment cuts: segment times are proportional to character count over the narration/video duration (global-speed style). If narration audio is longer than the video, the video plays slower (clamped 0.5–2.5×) so the narration fits — the same simplification as website v1. Subtitles during render follow the segment list, one cue line at a time, never a whole paragraph.

5. Settings

Audio modes use MediaRecorder with the canvas video track + a Web Audio track (Gemini TTS / uploaded file / original video). It may be slower and less frame-accurate than WebCodecs. During an audio-mode render the sound may play aloud — lower the phone speaker volume (capture is internal, so speaker volume does not mute the recording). If the output is still silent, report the log line "Audio track:" — that tells whether an audio track was found.

Speed here uses the browser playback rate and presented frames, so it is approximate, not frame-accurate like the server pipeline's per-segment speed change. The final summary reports the actual output duration, so you can see the real effect.
